# Bug audit — 25 October 2026

This review covers the integrated Windows dashboard and browser interface. It includes the pending microphone changes and CAT write fixes, plus the additional defects found during this audit. It is a source review and offline regression exercise, not a guarantee that all hardware/browser defects have been eliminated.

## Fixed in this update

| Problem | Change | Regression evidence |
| --- | --- | --- |
| Hamlib can silently ignore a mode change using an earlier TX reading. | Refresh PTT before normal and split-mode writes. Reject actual TX without unkeying another application. | Simulated TX-to-RX transition followed immediately by WSJT-X's `PKTUSB -1` command. |
| A successful Hamlib return does not always prove that a frequency/mode changed. | Confirm normal and split writes against radio readback, bypassing Hamlib's optimistic cache. Report requested/actual mismatches. Keep the dashboard's bounded shared readbacks. | Ignored frequency/mode writes return errors; subsequent writes recover; front-panel frequency changes do not suppress tuning. |
| A priority PTT-off could overtake an older queued PTT-on, which then keyed the radio afterward. | Cancel older queued dashboard and CAT transmit starts when a global release arrives. Preserve CAT promises so callers receive cancellation replies. | Blocked simulated radio operation, queued transmit start, then priority release; the old start is cancelled and the fixture remains in RX. |
| Ordinary browser command limits could reject PTT-off or microphone disarm during a burst. | Reserve pending capacity for releases and exempt them from the ordinary command-rate limit. Release flooding still closes the session and invokes ownership cleanup. | Burst of 45 ordinary commands remains limited while PTT-off and mic-disarm reach the handler. |
| An interrupted audio setup could continue over a replacement browser connection. | Recheck the audio epoch and client identity between asynchronous mapping, routing and microphone-registration steps. Stop obsolete capture streams. | Cancel microphone/listening setup during a delayed mapping acknowledgement; verify no registration or route-start reaches the replacement session. |
| A synchronous WebSocket send failure left a pending timer/editor lock until timeout. | Remove the command and matching edit immediately when `send()` throws. | Inject a failing socket send and verify no pending request or edit remains. |
| Quiet phone input was almost invisible on the linear mic meter. | Show local input on a logarithmic scale with raw/post-gain dBFS readings, limiter indication and missing-sample status. PTT is not needed to test this meter. | Synthetic AudioWorklet input at 44.1/48/96 kHz; verify gain, peaks, absent-input status and no microphone packets with PTT off. |
| iPhone microphone gain and return after app switching needed explicit controls. | Add saved local gain and opt-in restoration of a previously armed mic after confirmed RX and a fresh session/state exchange. Restoration never starts PTT. | Audio gain, ownership, capture interruption and obsolete-request tests; physical iPhone acceptance remains necessary. |
| Hamlib errors could expand into accumulated debug traces in the activity stream. | Log the concise operation/error message already used for radio status. | Build and existing failure-path regression suites. |

## Areas reviewed

- Radio queue ordering, command coalescing, generation checks, cancellation deadlines, normal/split writes, polling fairness and shared readback invalidation.
- CAT protocol parsing, VFO negotiation, multiple clients, startup capability queries, response deadlines, disconnect cleanup and PTT ownership/retry handling.
- Browser command acknowledgements, reconnection watchdogs, stale sockets, incremental state updates, settings drafts and preference-save ordering/failures.
- Browser microphone permission/interruption handling, gain and peak protection, PTT-gated PCM, receive playback and session restoration.
- HTTPS authentication/origin checks, passcode/session invalidation, WebSocket fragmentation, bounded buffers, slow-reader recovery and application/native heartbeats.
- Native layout at multiple DPI/window sizes, snapshot ordering and tuning-editor preservation.
- Saved connection/audio/scope configuration validation, explicit unavailable-device handling and no automatic device substitution.
- RF capture lifecycle, frame validation, waterfall history/freshness, audio route gates, device-management queues and shutdown ordering.
- Build/packaging allowlists and dependency notices. FTDI DLLs remain external downloads and are not committed.

## Verification

Build the application and all test targets, then run:

```powershell
ctest --test-dir build --output-on-failure
```

The six suites are `RadioChecks`, `ReleaseChecks`, `GuiChecks`, `BrowserChecks`, `WebDeltaChecks` and `WebServerChecks`. Radio checks use Hamlib Dummy or a loopback FT-710 emulator; web checks use an isolated loopback HTTPS fixture. They do not key the physical radio or open a physical microphone/audio route.

## Remaining hardware acceptance

- Recheck normal/split frequency and PKTUSB changes in WSJT-X with two CAT clients, especially immediately after TX ends and after front-panel tuning.
- Exercise Safari microphone gain, app switching, listening and reconnects on the actual iPhone/iOS version.
- Exercise FTDI capture and CAT-2 span changes on the actual radio, with SCU-LAN10 enabled.
- Check shutdown while the actual USB/audio drivers are active. An already-running Hamlib/driver call cannot be forcibly cancelled safely by the dashboard; queue cancellation prevents later stale commands from replaying.

Two clients can still deliberately request different frequencies or modes: they share one radio, so the last applied write determines its state. The dashboard reports confirmed values rather than assigning separate radio states to each client.
